# 🎹 피아노 악보 변환기

음악 파일(MP3·WAV·M4A 등)이나 마이크 녹음을 올리면 **음을 분석해서 피아노 악보를 그리고, 피아노 연주(MIDI·WAV)와 악보(MusicXML·PDF)를 만들어 주는** 웹사이트입니다.

- **서버가 필요 없습니다.** 모든 분석은 사용자의 브라우저 안에서 이루어지며 파일은 어디로도 전송되지 않습니다.
- 빌드 과정이 없는 정적 사이트입니다(HTML + ES 모듈). GitHub Pages 같은 정적 호스팅에 그대로 올리면 됩니다.

> ## ⚠️ 먼저 알아 둘 것: 완벽한 자동 전사는 불가능합니다
>
> 어떤 모델도 모든 음악을 틀림없이 악보로 옮기지 못합니다. 이 사이트의 결과는 **초안**이며, 필요하면 MusicXML/MIDI 로 내려받아 악보 편집기(MuseScore 등)에서 고쳐 쓰는 것을 전제로 합니다.
> - 녹음에서 들리는 소리는 "무엇을 연주했는가"를 완전히 담지 못합니다(페달로 겹친 울림, 여린 음, 배음, 잡음).
> - 같은 소리도 여러 방식으로 적을 수 있습니다(박자·음가·이명동음·손 나눔·꾸밈음 표기). 연주는 박자에서 늘 조금씩 벗어나므로, 어느 표기가 "정답"인지 소리만으로는 정할 수 없습니다.
> - 아래 수치는 모두 **특정 데이터에서 측정한 값**입니다. 다른 악기·장르·녹음 환경에서는 더 낮아집니다.

## 실행 방법

```bash
npm start            # http://localhost:8080  (의존성 없는 정적 서버)
```

- `index.html` 을 파일로 직접 열면(`file://`) 동작하지 않습니다. 마이크 녹음은 `https://` 또는 `localhost` 에서만 됩니다.
- 피아노 전용 AI 는 CPU 여러 개를 쓰기 위해 교차 출처 격리(COOP/COEP 헤더)가 필요합니다. `npm start` 서버는 헤더를 보내고, 헤더를 못 바꾸는 정적 호스팅(GitHub Pages 등)에서는 `coi-sw.js` 서비스 워커가 처음 한 번 새로 고침하며 켭니다. 켜지지 않아도 한 스레드로 동작합니다(느림).
- **브라우저**: 최신 Chrome / Edge 권장. (이 저장소는 헤드리스 Chromium 에서만 검증했습니다.)

## 사용 방법

1. 음악 파일을 끌어다 놓거나 **마이크로 녹음**하거나 **예시 곡**을 눌러 체험합니다(긴 곡은 처음 5분만 분석, 「분석 설정」에서 구간 변경).
2. 엔진 고르기: **피아노 독주 녹음 → 피아노 전용 AI(기본)**, 노래·밴드·합성음 → 범용 AI. 피아노 전용 AI 가 찾은 음이 매우 적으면 화면에 전환 안내가 뜹니다.
3. 리듬이 어긋나 보이면 **템포 ×2 / ÷2**, 1마디 첫 박이 틀리면 **마디 시작 위치**를 조정합니다.
4. 「검증 리포트」에서 경고를 확인하고, 들어 보며 고친 뒤 MIDI·MusicXML·WAV·PDF 로 내려받습니다.

## 동작 원리

```
오디오 ─▶ 디코딩 ─┬─ 44.1kHz 스테레오 ─▶ 피아노 전용 AI (Transkun v2, ONNX Runtime Web WASM)
                  │     멜 스펙트럼 → 트랜스포머 → 구간 점수 → semi-CRF 비터비 → 음(시작·끝·세기) + 서스테인/소프트 페달
                  └─ 22.05kHz 모노 ─┬─ 범용 AI (Basic Pitch, tfjs) + 배음 유령음 제거
                                    └─ 내장 (가변-Q 변환 → 하모닉 템플릿 NMF → 노트 트래킹)
음 → 온셋 곡선 → 템포 추정 → 동적계획법 비트 트래킹 → 마디 첫 박 · 조성 추정
음 + 박 격자 → [꾸밈음 라우팅: 앞꾸밈음·트릴은 격자 양자화를 거치지 않고 주음에 붙임]
            → 16분음표 양자화 → 양손 분리 → 마디·음가·붙임줄 → 페달 양자화 → 운지(DP)
            → VexFlow 악보 / MIDI / MusicXML / WAV   ─▶ 메타 검증 계층(단계 간 불변식)
```

### 피아노 전용 엔진을 브라우저에서 돌리는 방법

Transkun 은 PyTorch 모델입니다. `scripts/transkun/export_onnx.py` 로 신경망 부분(프레임 → 구간 점수·문맥 벡터)을 ONNX 로 내보내고, 원본의 파이썬 후처리(semi-CRF 비터비, 16초 구간 이어 붙이기, 겹침 정리)는 `js/analysis/transkun.js` 로 그대로 옮겼습니다.

- 구간 점수 행렬은 16초 구간마다 90×691×691(171MB)이지만, 비터비는 **양수 점수 구간만** 쓰므로(스킵 점수 0) 그 항목만 희소하게 내보냅니다(보통 수천 개). 결과는 원본과 같습니다(`tests/metrics.test.js` 에서 무작위 200사례로 확인).
- 같은 MAESTRO 곡 60초로 비교하면 JS 이식본과 PyTorch 원본의 음 1,105개가 모두 ±1ms 안에서 일치하고, 97%는 0.1ms·세기까지 같습니다(나머지는 부동소수 차이).
- 모델 파일 크기를 줄이려고 가중치를 float16 으로 저장합니다(27MB). 정확도 영향은 아래 표의 원본 비교 열을 보세요.
- WebGPU 는 이 모델의 희소 추출 연산(int64 인덱스 GatherND)을 지원하지 않아 쓰지 않았습니다. CPU(WASM SIMD, 최대 4스레드)로만 동작합니다.

## 정확도 (측정값과 조건)

자세한 표: [docs/benchmarks.md](docs/benchmarks.md) · 재현 방법: 아래 「벤치마크 재현」

**피아노 전용 AI — MAESTRO v3 테스트 세트 13곡(44분, 실제 그랜드 피아노 녹음), 배포되는 JS 이식본 그대로:**

| 지표 | 곡 평균 |
| --- | ---: |
| Onset F1 | **98.98%** |
| Onset+Offset F1 (페달 연장, MAESTRO 표준 채점) | **94.28%** |
| Onset+Offset F1 (건반을 뗀 시각 기준) | 87.83% |
| 처리 속도 (이 개발 환경 CPU, WASM 4스레드) | 실시간의 1.43배 |

- MAESTRO 는 이 모델의 **학습 데이터와 같은 종류**(같은 피아노·녹음 환경의 다른 연주)입니다. 다른 피아노·방·마이크로 녹음한 음원에서는 낮아집니다.
- 13곡은 테스트 세트(177곡)의 일부이고, 슈베르트 즉흥곡 Op.90-4 의 다른 연주가 5개 포함되어 있습니다.
- **합성음에서는 크게 떨어집니다**: 앱 안 합성 피아노 소리로 만든 곡에서는 정밀도 1.00 이지만 재현율 0.54~0.69 였습니다(실제 녹음으로만 학습된 모델이라). 그래서 예시 곡은 범용 AI 로 분석합니다.

**범용 AI / 내장 엔진 — 합성 피아노 음원 기준(실제 녹음 아님):** 범용 AI 앱 전체(악보 양자화 후 박 단위 비교) F1 0.90, 내장 엔진 음 검출 F1 0.70~0.80.

**잡음 환경** (피아노 전용 AI, 3곡 × 45초, 백색·분홍 잡음 SNR 20/10/0dB): 측정 진행 중 — 결과는 docs/benchmarks.md

## 요청 사양 대비 구현 현황

아래는 요청받은 방법론별로, 실제로 구현한 것과 구현하지 못한 것(이유 포함)입니다. **요청한 모델 중 상당수는 학습된 가중치가 공개되지 않았거나, 학습용 대규모 데이터·GPU 가 필요해 이 저장소에서 만들 수 없었습니다.** 이름만 붙인 가짜 구현은 넣지 않았습니다.

| 요청 | 결과 | 설명 |
| --- | --- | --- |
| OT-CRNN(SFT-CRNN + 하모닉 어텐션, OT 손실)을 주 전사 모델로 | ❌ → **대체** | 논문(arXiv:2605.17405)은 확인했지만 코드·가중치가 공개되지 않았습니다. 같은 논문의 비교표에서 onset F1 98.32%(SFT-CRNN 98.36%)·onset+offset F1 93.48%(SFT-CRNN 90.78%)인 **Transkun v2(MIT, 가중치 공개)** 를 브라우저로 이식해 주 엔진으로 썼습니다. |
| 희소 어텐션 Transformer + Mamba 로 추론 속도 확보 | ❌ | 새 구조는 다시 학습해야 해서 불가. 대신 희소 출력(171MB → 수 KB), WASM 멀티스레드, 서비스 워커로 정적 호스팅에서도 멀티스레드를 켰습니다. |
| TUTTI 합성 다악기 사전학습 → 미세조정 | ❌ | 논문(arXiv:2609.00640)은 코드·데이터 "공개 예정"이며 CC BY-NC-ND 입니다. 사전학습에는 대규모 GPU 학습이 필요합니다. |
| DiffRoll(생성형, 비지도 사전학습) 병렬 적용 | ❌ | 확산 모델은 추론에 반복 계산이 많아 브라우저 CPU 에 맞지 않고, 비지도 사전학습은 학습 인프라가 필요해 구현·검증하지 못했습니다. |
| EngravingGNN + End-to-End Transformer 병렬, 꾸밈음 구간은 Transformer 우선(동적 라우팅) | ⚠️ **부분 대체** | 주 엔진 Transkun 자체가 Transformer 전사 모델입니다. 꾸밈음·트릴로 판정된 구간은 16분음표 격자 양자화를 거치지 않고, **이 Transformer 의 원시 출력(실제 음·시각)을 MIDI·재생·검증에 우선 사용**하도록 라우팅합니다(악보에는 작은 음표·tr 로 표기, `js/music/ornaments.js`·`performanceNotes`). 판정은 규칙 기반이며, EngravingGNN 은 논문만 있고(Zenodo 에 PDF 만) 가중치를 찾지 못해 넣지 못했습니다. |
| TUTTI 교차 악기 전이 + Music-JEPA 계획 (무조·즉흥) | ❌ | Music-JEPA(arXiv:2607.22000)는 피아노롤로 소리를 예측하는 세계 모델이라 전사 모델이 아니고, 코드도 확인하지 못했습니다. 악기 무관 전사는 범용 AI(Basic Pitch)로 대신합니다. |
| ACDRL(잡음 인식 조건부 매핑 + 자기지도 마스크) + SNR별 잡음 증강 | ⚠️ **부분 대체** | 이 이름의 방법을 찾지 못했습니다. **SNR별 잡음 증강 평가**(백색·분홍 잡음 20/10/0dB)를 만들고, 정상 잡음 제거 전처리(최소 통계 잡음 추정 + 위너 이득, `js/eval/denoise.js`)를 시험했지만 **모든 조건에서 피아노 전용 AI 의 정확도를 오히려 낮춰** 앱에는 넣지 않았습니다. 잡음 환경의 "기존 대비"는 새 기본 엔진과 이전 기본 엔진을 같은 잡음에서 비교해 측정했습니다(아래 표). |
| 운지: PianoPlayer(RL) + 자기회귀 신경망 + GNN+RL, 확신도와 함께 "제안" | ⚠️ **대체** | 학습된 운지 모델 가중치가 없어 **Parncutt 계열 인체공학 비용 + 동적계획법(비터비)** 으로 구현하고, 전방-후방 알고리즘의 사후확률을 **확신도**로 표시합니다(`js/music/fingering.js`). 장음계(양손·1~2옥타브)·5음 자리·3화음에서 교본 운지와 일치하는 것을 테스트로 확인했습니다. |
| 검증: mir_eval + XSD + LilyPond 컴파일 + 가상 연주 + 메타 검증 계층 | ✅ | mir_eval 호환 채점(파이썬 mir_eval 과 소수 12자리 일치 확인), MusicXML 3.1 XSD 검증(xmllint), LilyPond 2.24 컴파일, 가상 연주 대조, 단계 간 불변식을 검사하는 메타 검증 계층(`js/validate/pipeline-check.js`, 앱 화면에도 표시). |

### 완료 조건 대비

| 조건 | 결과 |
| --- | --- |
| Onset F1 ≥ 0.98 | **조건부 충족** — MAESTRO 테스트 세트 13곡 평균 98.98% (PyTorch 원본 98.98%와 같음). 학습 데이터와 같은 종류의 녹음 기준이며, 합성음(재현율 0.54~0.69)이나 다른 녹음 환경·다른 악기에서는 보장되지 않습니다. |
| Onset&Offset F1 ≥ 0.95 | **미달** — 페달 연장 기준 94.28%, 건반 기준 87.83% (13곡 평균). 현재 공개된 어떤 피아노 전사 모델도 MAESTRO 에서 이 값을 보고하지 않았습니다(위 논문 표의 최고치 93.48%). |

## 한계 (도메인별)

- **악기·장르**: 피아노 전용 AI 는 피아노 독주 녹음으로만 학습됐습니다. 노래·밴드·오케스트라·전자음·합성음에서는 음을 많이 놓칩니다(범용 AI 가 낫지만 그래도 부정확). 여러 악기가 섞인 곡을 "피아노 편곡"해 주지는 않습니다 — 들리는 음을 옮길 뿐입니다.
- **녹음 환경**: 다른 피아노·방 울림·마이크·압축 음원(MP3)·배경 잡음에서는 정확도가 떨어집니다. 이 저장소에서는 MAESTRO(그랜드 피아노, 같은 녹음 환경)와 합성 잡음으로만 측정했습니다.
- **Offset(음 끝)**: 음이 언제 끝났는지는 페달·잔향 때문에 본질적으로 모호합니다. onset 보다 늘 낮습니다.
- **리듬 표기**: 16분음표 격자로 단순화합니다. 셋잇단음표·32분음표 이상·당김음·루바토가 심한 연주는 틀리게 적힙니다. 박자는 자동 추정하지 않습니다(4/4·3/4·2/4·6/8 선택). 빠른 곡은 템포가 절반으로 잡힐 수 있습니다(×2 버튼).
- **무조·즉흥 음악**: 조성 추정(피치클래스 통계)이 의미가 없고, 박 추적도 불안정합니다. 조성은 직접 고르세요.
- **꾸밈음**: 규칙 기반이라 턴·모르덴트·겹꾸밈음은 감지하지 않고, 빠른 음형을 꾸밈음으로 잘못 볼 수 있습니다. MAESTRO 정답 연주 13곡에 적용했을 때 감지율은 음의 0~1.4% 였지만, 꾸밈음 정답 주석이 있는 데이터가 없어 **정밀도는 측정하지 못했습니다**.
- **운지**: 손 크기·연주자 습관·앞뒤 문맥(3음 이상)을 반영하지 않는 단순 모델입니다. 확신도는 "다른 운지와 비교한 확신"이라, 비슷하게 좋은 운지가 여럿인 쉬운 곳에서 오히려 낮게 나옵니다.
- **손 나눔·성부**: 음높이와 화음 모양으로 나누는 규칙이라 손 교차·성부 진행은 반영하지 못합니다. 한 손 안에서는 단일 성부로만 적습니다.
- **조성·이명동음**: 조성 추정은 곡 일부만 분석하면 딸림조·관계조와 헷갈릴 수 있습니다(직접 선택 가능). 음이름은 조표 기준 단순 규칙입니다.
- **속도**: 피아노 전용 AI 는 CPU 로만 돌아 곡 길이의 1~2배 시간이 걸립니다(기기에 따라 다름). 처음 한 번 모델(약 29MB)과 런타임(14MB)을 받습니다.
- **검증 범위**: 헤드리스 Chromium 에서만 테스트했습니다. Safari/Firefox, 실제 GPU·마이크, 모바일 기기에서는 확인하지 못했습니다.

## 테스트와 검증

```bash
npm test             # 단위 테스트 (Node 22+, 설치 불필요)
npm run test:e2e     # 브라우저 E2E (Playwright + Chromium). data/maestro 가 있으면 실제 녹음 정확도까지 확인
npm run validate     # 검증 루프: 메타 검증 + MusicXML XSD(xmllint) + LilyPond 컴파일. 없는 도구는 건너뜀
```

## 벤치마크 재현

```bash
python3 scripts/eval/fetch_maestro.py      # MAESTRO 테스트 세트 13곡(약 450MB)을 Range 요청으로 data/maestro 에 받음
npm install                                # onnxruntime-web (Node 에서 WASM 실행)
npm run bench -- --out docs/benchmarks/maestro-clean.json
sh scripts/eval/noise-bench.sh             # 잡음 강건성 (피아노 전용 AI ± 잡음 제거)
npm install --no-save @spotify/basic-pitch@1.0.1 && sh scripts/eval/engines-noise.sh   # 이전 기본 엔진과 비교
npm run validate -- --out docs/benchmarks/validation.json
node scripts/eval/report.mjs               # docs/benchmarks.md 생성
```

모델 변환을 다시 하려면 `scripts/transkun/export_onnx.py` 의 안내(PyTorch CPU 판이면 충분)를 따르세요. 채점 기대값 픽스처는 `scripts/eval/make_metric_fixtures.py` 로 만듭니다.
